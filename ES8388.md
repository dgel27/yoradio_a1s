# ES8388 settings (ESP32-A1S)

Reference for the **Settings → es8388** group in the web UI, which controls the
ES8388 codec directly. Everything here is **hardware** and is stored per device
in EEPROM, so it survives a reflash.

### Audio chain

```
decoder → I2S → ES8388 master volume (main page) → [these settings] → amplifiers
```

The volume on the **main page** is the **ES8388's own DAC master volume**
(registers 26/27), not a software multiply, so it attenuates inside the codec
after the DAC. Its software stage is pinned to unity on ES8388 builds.

The trims on this page sit *after* the master volume, so they set the balance
between the two outputs rather than your listening level. Turn them down and the
main page slider tops out quieter on that output only.

---
### Volume and level

| Control | Range | Register | Meaning |
|---|---|---|---|
| **Master Volume (main page)** | 0–254 | 26/27 (0x1A/0x1B) | Set from the main-page slider, not here. **254 = 0 dB**, 0 = −60 dB usable span |
| **Speaker amp volume (LOUT1)** | 0–33 | 46/47 (0x2E/0x2F) | **30 = 0 dB**, 0 = −45 dB, 33 = +4.5 dB, 1.5 dB per step |
| **Headphone amp volume (LOUT2)** | 0–33 | 48/49 (0x30/0x31) | Same scale as OUT1 |
| **Speaker amp balance** | −6…+6 | 46/47 | Positive favours **left**; 1.5 dB per step on that channel |
| **Headphone amp balance** | −6…+6 | 48/49 | Same, for OUT2 |

On the ESP32-A1S, **OUT1 feeds the speaker amplifiers** (SPOLP/N → U4/U5 → J3/J4)
and **OUT2 feeds the headphone jack** (HPOUTL/R → J2). Some upstream example
files label these the other way round; the web UI labels are the correct ones.

Only the speaker path has a hardware enable: GPIO21 → R46 → the `CTRL` pin on
U4 and U5, with R51 pulling it down. The headphone jack has no such gate, so it
can only be muted through the codec's OUT2 enable bit (`ES8388_OUT2_MUTE`, the
settings-page "Mute headphone amp", and the jack-detect override).

Balance is an *offset* added to that channel's own volume, not a separate
attenuator, and the result is clamped at +4.5 dB. A channel already at 33 cannot
go higher. So +6 means "left 9 dB hotter than the base volume", not "left at
maximum".

### Sound shaping

| Control | Range | Register | Notes |
|---|---|---|---|
| **Stereo widening** | 0–7 | 29, bits 4:2 | The `SE` field. A stereo **widening** effect — it is **not** a tone EQ. The treble/bass/middle controls on the main page are software biquads |
| **DAC Vpp scale** | 0–3 | 29, bits 1:0 | 0 = 3.5 V, 1 = 4.0 V, 2 = 3.0 V, 3 = 2.5 V. Lower gives more headroom and less level |
| **De-emphasis** | 0–3 | 28, bits 7:6 | 0 = off, 1 = 32 kHz, 2 = 44.1 kHz, 3 = 48 kHz |
| **Mono downmix** | on/off | 29, bit 5 | (L+R)/2 into both channels |
| **Soft volume ramp** | on/off | 25, bit 5 + 7:6 | Ramps the volume instead of stepping it, which removes the click on every volume change |

**Leave De-emphasis at 0 for internet radio.** It exists for broadcast material
that was recorded with pre-emphasis; enabling it on already-corrected streams
thins out the treble.

**Keep Soft volume ramp on** unless you have a reason to disable it. The factory
default is on.

### Amplifier and power

| Control | Range | Register | Notes |
|---|---|---|---|
| **Mute speaker amp** | on/off | GPIO 21 | Gates the on-board amplifier. Separate from the codec's own output mutes |
| **High output impedance (40k)** | on/off | 45 (0x2D) | off = 1.5 kΩ, on = 40 kΩ. Only matters when driving a long cable or a high-impedance input |
| **Standby when stopped** | on/off | power registers | Parks the codec while nothing is playing and wakes it on play. Saves idle power |

### Line-in and microphone

| Control | Range | Register | Notes |
|---|---|---|---|
| **Line-in routing** | off / mix / line only | 39 (0x27), 42 (0x2a) + `DACMute` | see below. **Leave off** with nothing plugged into the line jack, or you amplify noise |
| **Line-in level** | −15…+6 dB, 3 dB steps | 39/42 bits 5:3 | how loud line-in sits relative to the radio |
| **Power up ADC (record)** | on/off | 3 (0x03) | The ADC is **not used for playback**. yoRadio has no recording feature yet, so this only raises idle power draw |
| **Mic preamp gain** | 0–8 | ADC PGA | 0 to +24 dB in 3 dB steps |
| **Mic input** | 0–2 | ADC input | 0 = LIN1 & RIN1, 1 = LIN2 & RIN2, 2 = differential |
| **Mic bias (MBIAS)** | on/off | MBIAS | Microphone power rail. Electret mics need this **on**; dynamic mics do not |

The three microphone settings have **no effect while ADC power is off**, which is
the default. Select a mic input first, then enable ADC power if you ever need it.

#### Line-in routing

The line jack is summed inside the codec at registers 39 and 42, which sit
**downstream of the DAC**. The radio arrives through the DAC's digital path. That
one fact decides all three modes:

| Mode | Line-in bit | `DACMute` (reg 25) | Result |
|---|---|---|---|
| off | 0 | 0 | radio only |
| mix | 1 | 0 | radio **and** line-in, ratio from the level control |
| line only | 1 | 1 | line-in only — the radio's digital path is muted, which line-in survives |

**The main-page volume does not reach line-in.** Volume is a digital attenuator
at registers 26/27; line-in joins downstream of it, so no setting of the main
volume changes line-in's level. The dedicated level control above is the only
fine one, and it moves in 3 dB steps.

Two things that follow from the same fact:

- In **line only** mode the existing speaker/headphone volume sliders
  (`esvol1` / `esvol2`, registers 46–49) act as a line-in fader over roughly
  45 dB, because they are *after* the mixer. That is the finer control in that
  mode.
- **Equalisation does not apply to line-in.** The tone controls are biquads in
  `Audio::playSample()`, which only ever sees decoded I2S samples; the ES8388 has
  no analog filter on the line-in path. Same for mono, stereo widening, Vpp scale
  and the VU meter — all DAC-digital.

Getting EQ on line-in would mean routing it through the ADC into I2S instead:
full-duplex I2S, a read path, and a clocking decision, since the ADC would have
to run at the stream's sample rate. Not implemented.

### Settings with no web control

Four stored values exist in EEPROM but are reachable only over telnet, because
they fix hardware problems rather than being everyday settings:

| Telnet command | Setting |
|---|---|
| `esclick on\|off` | Click-free power up/down (register 28, bit 3) — the codec's own anti-thump, on by default |
| `esinvl on\|off` | Invert left channel phase (register 28, bit 5) — for a swapped or inverted wiring fault |
| `esinvr on\|off` | Invert right channel phase (register 28, bit 4) |
| `esramprate 0..3` | Soft-ramp speed: 0.5 dB per 4 / 32 / 64 / 128 LRCK |

See `help` over telnet for the rest of the ES8388 commands, including `esdump`
(dump registers 0–63) and `esregr` / `esregw` for raw register access.

### Practical notes

- **The ↺ reset button** next to the "ES8388 codec" heading restores every value
  on this page to the factory defaults compiled in from `myoptions.h`
  (`examples/myoptions-a1s.h` in this repo). Over telnet the same thing is
  `esreset`.
- **These values are per device.** They are stored in EEPROM and survive
  reflashing and rebooting. `myoptions.h` only supplies the *initial* values,
  and only after a reset or a factory reset.
- **The per-output trims multiply with the main page.** Master volume is set
  from the main page; the trims here scale each output relative to it. Leave
  both trims at 30 (0 dB) unless you want the two outputs to differ.
- **If you hear distortion at high volume**, lower the main-page slider or set
  **DAC Vpp scale** to 1, then press reset. This is analog headroom, which the
  digital volume cannot recover.
- The software chain can never exceed the decoder's own output (each sample is
  halved and the biquad gains are clamped to +6 dB), so a master volume of 254
  cannot cause *digital* clipping. `Gain()` does no scaling at all on ES8388
  builds: volume and balance are both applied in the codec. Any distortion comes
  from the analog stage or the amplifier.
